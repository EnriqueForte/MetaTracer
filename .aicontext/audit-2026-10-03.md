# Auditoría completa de MetaTracer (2026-10-03)

**Proyecto:** MetaTracer (v0.6.0)
**Ámbito:** código completo — `core/`, `extractors/`, `detectors/`, `classification/`, `agents/`, `knowledge/`, `reports/`, `api/`, `services/`, `db/`, `cli/`, `scopes/`, Web V1 (Jinja + Alpine) y Web V2 (`web/`, Next.js), `pyproject.toml`, `Dockerfile`, `docker-compose.yml`, `.env.example`, tests.
**Método:** revisión estática en cuatro bloques paralelos (safety + extracción, pipeline de análisis, API + backend, UI) y verificación manual de los hallazgos de mayor severidad. No se ejecutaron `pytest` ni `ruff` en esta auditoría.
**Veredicto:** ✅ **sin violaciones de las 7 reglas inviolables**. Hay ~10 problemas reales a corregir antes de exponer la plataforma en red o a varios usuarios.
**Tasks derivadas:** [TASK-27](tasks/27-security-hardening-p0.md) → [TASK-34](tasks/34-detector-precision.md) (v3.2 "Hardening post-auditoría") y [TASK-35](tasks/35-ui-ux-improvements.md) (mejoras UI/UX de la Web V2, § 3, más estado de triage `false_positive` y light mode).

### P2 — higiene

**Safety core y supply chain → [TASK-32](tasks/32-core-hygiene.md)**

- `METATRACER_ALLOW_LOOPBACK` activable en cualquier despliegue (sin kill-switch fuera de pytest) — `core/config.py` L36–37.
- Rangos IP no bloqueados: `192.0.0.0/24`, `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, `198.18.0.0/15`, `240.0.0.0/4`, `2001:db8::/32` — `core/safety/guard.py` L21–38.
- IDN/punycode normalizado distinto en scope (`normalize_host`) y transporte (`urlsplit().hostname`).
- `ApiRateLimiter.check` hace `await` con el lock tomado — `core/ratelimit.py` L96–115.
- Recursión mutua sin tope en el parser JS (`_skip_string` ↔ `_skip_template_expr`) — `extractors/javascript.py` L67–102.
- GET tras HEAD re-recorre la cadena de redirects (2× slots de rate limit) — `core/safety/http.py` L156–214.
- `piexif` en runtime aunque solo se usa en tests; versiones `>=` sin lockfile; tag de imagen `0.5.1` vs paquete `0.6.0`; `POSTGRES_PASSWORD` con default débil.
- Menores: `Image.MAX_IMAGE_PIXELS` no fijado explícitamente; Content-Type vacío tratado como HTML; scopes de una sola etiqueta (`*.com`) aceptados; sweep de temporales huérfanos al arrancar.

**Backend → [TASK-33](tasks/33-backend-hygiene.md)**

- SSE colgado si el historial del `ProgressBus` se evictó y el run ya es terminal — `services/progress.py` L46–59; `api/runs.py` L134–164.
- Reintentos de webhook dependen del siguiente evento terminal — `api/webhooks.py` L414–489.
- Índice ausente en `Run.started_at` (el comentario dice que existe) — `db/models.py` L134; `db/repositories.py` L77–79.
- Drift modelo ↔ Alembic en `webhook_config.name` (nullable).
- Dashboard y `DeltaReporter` cargan todo en memoria / N+1 — `db/repositories.py` L382–427; `services/watch.py` L82–91.
- Login sin lockout por cuenta; timing oracle en invitaciones usadas/expiradas; carrera en first-run setup — `api/auth.py`.
- Import circular `classification` ↔ `agents`; código muerto `GraphNodes` (`agents/graph.py` L117–125); regex duplicadas `debug.py`/`classifier.py`.
- `/api/ready` con ping a BD; export KB borra el temporal a los 2 s; comentario desactualizado de `ProgressBus`.

**Precisión de detección → [TASK-34](tasks/34-detector-precision.md)**

- Email: `image@2x.png`, `logo@3x.jpg` detectados; `example.net`, `test.com` no filtrados — `detectors/email.py`.
- GPS casi-(0,0) emite finding y se renderiza `0.000000, 0.000000` — `detectors/gps.py` L107–114.
- Marcador de secreto sin valor (`"credentials"`) → `critical` — `classification/classifier.py` L50, L251–253.
- Rúbrica GPS `critical` inalcanzable (el snippet nunca lleva contexto) — `classification/rubric.py`.

- Coste LLM: el cap de findings agentizados es `max_assets_per_run`; llamadas secuenciales sin caché — `agents/pipeline.py` L190.

## 2. Mejoras funcionales (backlog, sin task asignada)

**Detección:** nuevo `finding_type` `secret` (AWS `AKIA…`, `ghp_`, JWT, PEM); IPs privadas y hostnames internos (`.corp`, `.internal`); autor/usuario sin email (EXIF Artist, PDF Author, `dc:creator`); URLs de buckets cloud. Requiere actualizar antes los contratos de `tasks/README.md`.

**Extracción / crawl:** `srcset`, `<picture>`, `og:image`, CSS `url()` (S); GIF y SVG (S–M); `docProps` de DOCX/XLSX/PPTX con tope anti zip-bomb (M); `robots.txt` + `sitemap.xml` in-scope (M); profundidad configurable con presupuesto (M); HEIC/AVIF y JS renderizado (L, impacto supply chain).

**Plataforma:** estados de triage (`open`/`confirmed`/`false_positive`/`fixed`); diff de runs en UI (reutiliza `DeltaReporter`); tokens de API para CI; audit log; scans programados desde el API; métricas Prometheus; versionado `/api/v1`; proyectos/aislamiento multi-tenant.

**Reportes:** SARIF 2.1.0; plantillas HackerOne/Bugcrowd; `max_agent_findings` + concurrencia acotada + caché de respuestas LLM.

## 3. UI/UX y diseño

La Web V2 cubre ~95% de las pantallas V1; no faltan pantallas núcleo.

**Arreglos rápidos (S)**

1. Filtros activos invisibles: `Button` sin estilo `aria-pressed` (`web/src/components/ui/button.tsx`); V1 sí lo tenía.
2. Falta filtro `Unclassified` en `findings-panel.tsx`.
3. Campana sin enlace al run: `web/src/lib/api/browser.ts` descarta `run_id` y `created_at`.
4. Sin botón Copy del código de invitación (`users-view.tsx`).
5. Drawer de feedback visible para viewers (403 al usarlo).
6. Wizard ignora en silencio dominios manuales si hay scopes guardados.
7. Modal de scope sin focus trap (existe `ui/dialog.tsx` de Radix sin usar).
8. Errores de import de scopes genéricos; `Space` no abre filas; aviso ético reducido.

**Nuevas funcionalidades de UI:** filtros en URL (`?severity=&type=&q=`); mapa para findings GPS (sin tiles de CDN); paleta de comandos Ctrl+K y atajos `/`, `j`/`k`, `Esc`; diff de runs y tendencias de severidad (requiere series en `/api/stats`); acción "Dismiss / false positive"; pantallas Knowledge y Webhooks; botón abort; onboarding.

**Calidad del frontend:** la arquitectura pide TanStack Query + Zod, el código usa `useEffect` + parsers manuales y `schema.d.ts` no se importa; `findings-panel.tsx` (~586 L) y `run-progress.tsx` (~416 L) a trocear; virtualización de tablas grandes; pill `border-radius: 999px` y animación en bucle `.mt-stage-asset` contradicen la dirección visual.

**Diff sin commit (2026-10-03):** el marcador de etapa en `run-progress` es correcto; `AssetFindings` agrupa todos los findings ignorando filtros y sus badges no son clicables (filtrar + abrir sheet, o retirarlo); "Recent progress" repite el mensaje visible.

## 4. Fortalezas a conservar

- `safe_httpx_request` como único punto de salida; redirects revalidados por hop; scope robusto frente a lookalikes; guard con IPv4-mapped y metadata cloud.
- Clasificación por magic bytes; cero bytes en BD y LLM; `sanitize_for_log`.
- Severity NULL en detectores, techos por tipo, guard que solo baja, fallback heurístico, payload cerrado al LLM.
- Un único `ScanOrchestratorService` para CLI y API.
- Auth (cuando está activa): CSRF double-submit, rotación de sesión, tokens hasheados, invitaciones atómicas.
- V2: sin `dangerouslySetInnerHTML`, `safeUrl`, estados empty/error/failed/aborted diferenciados, `prefers-reduced-motion`.
